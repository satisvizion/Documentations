Overview

Bus Crowd — Traffic Jam is a portrait traffic-puzzle game for Unity 6000.0.62f1 (URP). A depot of parked buses faces a crowd of coloured passengers queuing around a ring road. The player taps a bus whose path out of the depot is clear; it drives to one of four parking bays and passengers of its colour board it. A full bus drives away and frees its bay. Every bus must leave before the attempt timer runs out.

The package contains a 500-level validated campaign, three boosters on the HyperCasualLiveOpsKit (HLK) booster bar, mystery buses, a level editor and an automatic level generator, and the HLK menu, economy, results and LiveOps screens configured for this game in a LocalQA profile (simulated ads and purchases).

This is a technical handoff candidate. Desktop gameplay, the level tools and local Windows/Android builds were exercised. Native-device acceptance, live ad/billing/game-service providers, original sound authorship review and owner-confirmed asset provenance (see AI-DISCLOSURE.txt) remain open. It is not a store-release certification.

Getting Started

  1. Create a Unity 6000.0.62f1 project with the Universal Render Pipeline. Install com.unity.inputsystem and com.unity.ugui, then import TMP Essential Resources (Window → TextMeshPro → Import TMP Essential Resources).
  2. Import the package. It creates two folders: Assets/Game and Assets/HyperCasualLiveOpsKit.
  3. Assign the included pipeline asset Assets/Game/ProjectRenderSettings/PC_RPAsset.asset under Project Settings → Graphics (and Quality), and set the colour space to Linear.
  4. Add the scenes to Build Settings in this order: Assets/HyperCasualLiveOpsKit/StarterMenu/Scenes/HLK_MainMenu.unity, then Assets/Game/Scenes/Game.unity.
  5. Open HLK_MainMenu and press Play. PLAY NEXT LEVEL starts level 1, the guided tutorial.

Set Player Settings → Resolution to a portrait window (for example 540 × 960) for desktop testing. The game fits its board between the HLK top bar, the booster shelf and the banner lane on any portrait aspect.

Gameplay

  • Dispatch. Tap a bus. If nothing stands in its exit path and a bay is free, it drives to the bay. A blocked bus bumps the blocker and returns; with all four bays taken the tap is refused ("Slots Full").
  • Boarding. The passenger at the front of the ring boards a parked bus of the same colour. Rows of four keep coming from one or two feeder arms. Long, medium and small buses hold different numbers of riders.
  • Leaving. A full bus drives away and frees its bay. The level is won when every bus has left.
  • Timer. Each level has an attempt time limit (from the level JSON, scaled by chapter). When it runs out the level is lost; TRY AGAIN restarts the attempt.
  • Mystery buses (from chapter 5) show a “?” cover and cannot be dispatched until the stated number of other buses have left; then their colour is revealed.
  • Tutorial. Level 1 guides the first four dispatches with a hand pointer.

Win/lose settlement goes through HLK once per attempt: a win credits the configured coin reward and opens the results overlay; a loss credits nothing. Gameplay sound cues (bus released, blocked tap, full bus, mystery reveal, win, lose) are played through the HLK sound bank and follow the Settings sound toggle.

Level Editor

The current preview draws vehicle lengths, widths and routes at the same fitted physical-world scale. Controls use normal editor layout so dummy Layout-event rectangles do not clip the control rows. Recorded evidence levels remain read-only in this canvas; their first-layout preview is guarded.

Open Tools → BusCrowd → Level Editor. The window lists all published levels with a live canvas preview of the depot (bus sizes, colours and headings, mystery marks), the crowd rows and the saved witness order.

  • Validate selected checks the selected level's rules (every bus can leave, per-colour seats equal waiting passengers, bays and timer) and replays its saved witness to a win.
  • Duplicate, Delete, Up/Down reorder the campaign; Undo reverts the last edit (up to 64).
  • Apply data edit (invalidates witness) applies a hand edit of the level payload. The old witness no longer proves the edited level, so validation fails until a new proven order is stored (regenerate the level if needed).
  • Play saved level opens the gameplay scene on the selected level.
  • Validate + save validates the whole campaign first; publication is staged and swapped in one step, and an invalid or cancelled save leaves the existing JSON untouched. Previous versions are kept under Artifacts/Phase04/Backups. Reload discards unsaved edits.

Levels 1 and 200 are the recorded source levels and must stay in place; the campaign check refuses a save that moves them.

Automatic Level Generator

Open Tools → BusCrowd → Auto Level Generator (the same window; the generator controls are in the lower panel). The saved request holds count, seed, attemptsPerLevel, minimumFormations, maximumRepeatStreak and append. In a fresh project it is recreated from the campaign's own CampaignAuthoring.json.

Generation is constructive: it picks a formation for the level's chapter, builds a blocking order from the real sweep rules, generates the crowd sequence (with decoys), and proves a witness dispatch order by replaying it through the actual GameSim. A candidate that fails validation or its witness is retried. With append on, existing levels are kept byte-for-byte and only new ones are added (for example count 502 appends levels 501–502). The same seed reproduces the same campaign. Generate into editor (review, then save) fills the editor with the result; nothing is published until Validate + save. Save request stores the settings.

Boosters

BoosterEffectStart count
Crowd ShuffleBrings a row of a parked bus's colour forward in the queue (instant). Refused when no row matches.2 on unlock
BalloonArm, then tap a blocked bus: it is lifted straight into a free bay. Missed taps and hidden buses keep it armed at no cost; a second press cancels.2 on unlock
Bus ShuffleSwaps equal-size waiting buses in a short staggered flight; taps wait until they land.2 on unlock

Crowd Shuffle, Balloon and Bus Shuffle unlock at player levels 2, 7 and 12 respectively. Each receives two initial uses and is consumed once per successful activation. The current progression policy is included in the current-delivery section; per-booster offer overrides take precedence. Counts, prices and unlock level are defined in Game/Integration/PowerUps/*.asset and the HLK power-up catalog.

Level Variation

The campaign has nine chapters: First taps, Blocked paths, Cars and decoys, Two arms, Mystery buses, Dense depots, Super hard, Master depots and Grand master. Chapters raise the bus count (4–6 in chapter 1 up to 60–84 in chapter 9), colours, blocking depth, decoy ratio and mystery buses, and tighten the time factor; recovery levels follow difficulty peaks. Two board templates (A: large buses, B: the Level 200 depot), three crowd topologies (left arm, right arm, both arms) and twelve formation families with dense variants give 190 distinct depot formations in the current campaign with no formation repeated more than twice in a row.

Customization Guide

  • Win reward, menu copy, level count: HyperCasualLiveOpsKit/StarterMenu/Resources/HLK/StarterMenuConfig.asset.
  • Economy, ads, purchases, services: HLKSettings (see the kit manual). Replace LocalQA/mock providers with real ones before release.
  • Colours and palette: Game/Resources/palette.json.
  • Vehicle models: Game/Resources/Generated/*.glb; the procedural fallback is used when GeneratedModels.Enabled is false.
  • Timing: per-level timeLimitSeconds and the chapter time factor in Campaign/Progression.cs.
  • New levels: use the editor/generator rather than editing JSON by hand, so each level keeps a proven witness.

Level Format

Each level is one JSON file. Coordinates are normalised to the portrait design frame. Key fields: vehicles (id, colour, size, capacity, x, y, headingDeg, length, width), slots (the four bays), crowd (rowSize, the ring path and its queued rows as [colour, row count], feeder arms), timeLimitSeconds, mystery (bus id + reveal count), generator (formation provenance) and solution (the proven witness order and its duration). Safe worked editing procedure

  1. Open Level 4 in the Level Editor, duplicate it and move the duplicate to the end. Preserve the recorded source levels at positions 1 and 200 before saving.
  2. Use the editor’s supported controls for a small placement change; keep legal occupancy and required targets. Do not invent JSON fields.
  3. Run the shipped validator, correct any rule errors, save, then open the duplicate in gameplay and complete it.
  4. For generation, record the current seed, request a small append batch using the exposed controls, validate its solutions and confirm the previous campaign prefix is unchanged. Cancelling must leave the campaign unchanged.

Run these procedures in a clean import of the final candidate before claiming buyer acceptance; restore test additions afterward.
