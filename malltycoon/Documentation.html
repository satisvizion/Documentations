Mall Tycoon

Developer manual · Version 1.0.1 · SatisVizion · Documentation revised 26 October 2026

Overview and included content

Drag anywhere to walk using the virtual joystick. Stand behind counters to serve shoppers, collect cash, stand on purchase pads to open shops or hire helpers, and carry boxes from the stockroom to restock shelves.

This is an editable Unity game template and starting point for your own title. Customize the visuals, copy, level progression and release settings for your audience, then test your changes. The included Android demo is a showcase build; it is not a signing key or a production store submission.

Shops, shopper queues, restocking, litter, staff, permanent upgrades, rank XP and guided level objectives. The simulation has no countdown loss timer. The campaign contains 25 authored levels and game-specific procedural continuation. The included service kit is HyperCasual LiveOps Kit. Ads ship in Dummy/simulated mode and IAP is Disabled; third-party advertising/billing SDKs are not bundled.

Installation and first successful play

  1. Back up your project and extract the main ZIP completely. Read Documentation/Documentation.html before importing the package. Offline documents do not require the hosted page to be available.
  2. Install Unity 6000.0.62f1 through Unity Hub. Add Android Build Support (including the matching SDK, NDK and OpenJDK) if building Android, and WebGL Build Support if building browser demos. A supplied source project can be opened with Add project in Unity Hub.
  3. For package import into a new project, select a Universal Render Pipeline template. Use Assets > Import Package > Custom Package and import the complete package. Do not omit the private game Kit, HyperCasualLiveOpsKit, fonts, settings, scenes or their .meta files.
  4. Check Window > Package Manager: Universal RP 17.0.4, Unity UI 2.0.0 and Input System 1.14.2. Standard Unity modules include com.unity.modules.screencapture and com.unity.modules.androidjni. Let Unity finish compilation before opening a scene.
  5. Set Edit > Project Settings > Player > Other Settings > Active Input Handling to Both manually. Restart if Unity requests it. The documented setup is a user action; do not rely on an import hook changing a buyer's Project Settings.
  6. In Edit > Project Settings > Graphics select the supplied URP asset, and check the pipeline assignment for the active Quality level. Retain the packaged Settings assets and GUID references. A pink scene usually indicates a missing pipeline or shader assignment.
  7. Open Assets/Games/MallTycoon/Scenes/MallTycoon_Mobile.unity. Press Play, focus the Game view, and follow the first-level tutorial: Drag anywhere to walk using the virtual joystick. Stand behind counters to serve shoppers, collect cash, stand on purchase pads to open shops or hire helpers, and carry boxes from the stockroom to restock shelves.
  8. Stop Play mode before editing source or authored content. Open the landscape scene Assets/Games/MallTycoon/Scenes/MallTycoon_WebGL.unity and verify the alternate layout as well. Runtime-created UI changes made only in Play mode are not a saved reskin.

2. Change a visible HUD label

Open Assets/Games/MallTycoon/Scripts/MallTycoonGame.Hud.cs, find RefreshHud and locate this exact source line:

if (_sideLevel) { _sideLevel.text = "Level " + _playLevel.ToString(CultureInfo.InvariantCulture); _sideName.text = D.name; }

To call levels stages, change the display string while preserving the level expression and formatting:

if (_sideLevel) { _sideLevel.text = "Stage " + _playLevel.ToString(CultureInfo.InvariantCulture); _sideName.text = D.name; }

This is a targeted edit to the displayed string, not a global search/replace of object names. HzUI.Label("Lvl", parent, "LEVEL " + Level, ...) uses its first string as a hierarchy/object name and its third argument as visible text. In assignments such as _levelTxt.text = ..., edit only the literal part; retain the number, interpolation braces, arithmetic, conditional branches and formatting.

4. What the shared localization guide does and does not cover

The shared HyperCasual LiveOps Kit localization guide concerns UI and content that use that kit's localization service. This game's literal strings in the files above are not automatically replaced by adding entries to an HLK table. For one-language reskinning, edit the literals and data shown here. For runtime language selection, explicitly route those game display assignments through your chosen lookup service, provide keys for each caption, and refresh active labels when the language changes. That is an integration task, not a delivered translation toggle.

Shop and upgrade wording can also come from data definitions and arrays in the game scripts. In MallTycoonGame.Hud.cs, BuildSides contains the visible Mall Tycoon title, BuildUpgradeRows selects UPGRADES / STAFF, and HelpPage supplies HOW TO PLAY. Changing a shop identifier, save key or upgrade index is not a translation. Keep upgrade costs, staff behaviour and task checks intact when changing a caption. MtArt.Themes colours the floor/walls; it is separate from HUD colours such as HudNavy, TaskCream and TaskTitle.

5. Verify the reskin

  1. Launch both supplied scenes with a normal player save. Confirm the edited level heading, game title, settings/help buttons, counters and booster names.
  2. Open a result popup and a refill offer, and replay the first-level and first-booster tutorials using a disposable test profile or the documented developer controls. Confirm that the changed colours remain readable behind all overlays.
  3. Test one valid move, one invalid action, progression to the next level, a retry and one available booster. A text reskin must not change goals, costs, rule checks or resource IDs.
  4. Make a new Android/WebGL test build after source edits. Existing hosted demos and videos will continue to show their previously built appearance until rebuilt; editing this manual alone does not change those binaries.

Gameplay and content

Drag anywhere to walk using the virtual joystick. Stand behind counters to serve shoppers, collect cash, stand on purchase pads to open shops or hire helpers, and carry boxes from the stockroom to restock shelves.

Shops, shopper queues, restocking, litter, staff, permanent upgrades, rank XP and guided level objectives. The simulation has no countdown loss timer.

The source includes 25 authored levels and seeded procedural continuation. Progress, settings and charges are stored locally with PlayerPrefs. Browser storage depends on the browser profile. The template includes source and editable level data; generated continuation is not advertised as hundreds of individually authored levels.

Boosters

  • Roller Skates unlocks at level 3.
  • Cash Magnet unlocks at level 7.
  • Happy Tunes unlocks at level 11.
  • Extra Hands unlocks at level 15.

First-use guidance introduces each booster. Availability depends on the level, current state and remaining charges. Rewarded placements are simulated by default; only a completed reward callback should grant a refill. Use the DEV panel to unlock boosters for authoring, not as a substitute for real progression testing.

Manual editor and generation

Open Mall Tycoon > Level Editor. Duplicate a level before changing the original tutorial. The authoring file is Assets/Games/MallTycoon/Resources/malltycoon/Levels/levels.json.

Click a booth slot to place or cycle a shop type; right-click removes it. Select each shop to configure price, helper and stock. Set the level goal, target, rows, shopper patience, restocking, litter and starting economy. Keep the entrance and walking paths usable. Validate the actual simulation result before saving. Time values in authored data are simulation tuning/proof inputs; the shipped player flow has no countdown loss timer. Generated shifts continue after the authored campaign.

The included editor supports saving, duplication and ordering, and provides generation and validation controls appropriate for this game. Read the actual validation result; a difficulty target is not a guarantee of player success. Use a repeatable seed when comparing generated variants. Test changed boards in Play mode.

LiveOps, ads and haptics

The publisher-owned HyperCasual LiveOps Kit is included. Read its complete offline manual.

Settings: Assets/HyperCasualLiveOpsKit/Resources/HLK/HLKSettings.asset. Shipping defaults are Ads Mode Dummy (0) and IAP Mode Disabled (3). Banner, interstitial and rewarded placements are simulations. No Google Mobile Ads, billing or other vendor SDK is included. Automatic vendor-SDK installers are disabled. The game's own Kit is required code, not an advertising SDK.

To enable a real provider, separately install its official SDK, follow the kit manual, configure your own identifiers, consent and privacy policy, then test the selected platform and all cancellation/failure cases. Do not enable SDK symbols without the corresponding dependency. Optional kit modules are capabilities, not production services already configured for this game. Native vibration needs a supported device; browser haptics and other native services have platform limits.

Development controls

Open DEV, press F2/backquote, or use the kit's top-left multi-tap shortcut. The global panel supports level jumps, booster access, ads and haptics controls. Add HZ_RELEASE to scripting defines when you want these development controls excluded from a consumer build. This does not configure real ads or certify store readiness.

Android release

Use the Mobile scene, portrait orientation and ARM64/IL2CPP with matching Unity tools. The provided APK is a debug-signed development demo, not a production store release. For release turn off Development Build and debugging, choose your own application identifier and review current store API requirements.

In Player → Publishing Settings create or select your own keystore and alias. Securely retain the keystore, alias and passwords for future updates; never redistribute signing secrets. Enable Build App Bundle for a Google Play AAB. Install a release candidate on a physical Android device and check touch, audio, haptics, pause/resume, saves and any enabled provider flows. Complete destination-store ads/data declarations and your privacy policy for the services actually enabled.

WebGL

Build the Mobile scene for a portrait-only demo with the built-in Default template and Brotli decompression fallback. Use Mall Tycoon → Create Responsive WebGL Page after building and select the output folder. This generates an original responsive page around the complete Build folder. Serve every loader, framework, data and WASM file over HTTP(S); file:// is unsupported. Audio normally starts after a first click/tap.

The two-scene landscape-first route supports ?mobile=1 to switch to the following Mobile scene. The included WebGL build menu uses HLK's non-development local showcase scope. It supports simulated demos; configure your production providers and resolve the kit build-doctor checks for a real service release.

Troubleshooting

  • Missing types: install the required packages and import all three roots, preserving .meta files.
  • Pointer input exception: select Active Input Handling Both and restart Unity.
  • Pink materials: use URP 17.0.4 and run the game's Setup command.
  • Sparse scene in edit mode: world/UI objects are built at runtime; press Play.
  • No real ad revenue: Dummy mode is simulated and no provider SDK is bundled.
  • IAP is unavailable: it is deliberately Disabled by default; configure an official billing integration separately if you need it.
  • Progress persists: use the development reset controls or deliberately clear this product's PlayerPrefs.
  • WebGL does not load from a local file: serve the complete output over HTTP(S).

Procedural generation and level data reference

The level data used by this game is located here: Assets/Games/MallTycoon/Resources/malltycoon/Levels/levels.json. Generation logic is in Assets/Games/MallTycoon/Scripts/MtGen.cs. Keep the authored campaign and generated continuation distinct when estimating your content count.

Generation controls exposed by the game editor include: Seed, Breather, Breather drop, Seed base, Generate + validate.

  1. Back up the level JSON before a generation operation. Choose a small trial range and a repeatable seed first, then inspect what is appended or replaced. Do not assume a command is append-only; a selected-level regeneration or Rebuild command can replace authored content.
  2. Read the game-specific fields in the level editor and generator source. Match generated board dimensions, rule limits and special mechanics to the intended difficulty; do not copy parameters from another game.
  3. Validate generated output, play several early/mid/late boards, and check that the tutorial still introduces mechanics before the generated content requires them. Keep a saved known-good seed for regressions.
  4. Treat visual difficulty labels and bot/solver scores as authoring aids. They do not guarantee that every generated board is suitable for every player or that a target completion time is achievable.

Game text versus saved data and service configuration

Game progress, tutorial flags, currency and booster inventory are stored through the private HzSave helper and Unity PlayerPrefs. Search that helper and the main game script for the current key prefix. Changing displayed titles does not require changing those keys. Renaming keys can make an existing player appear to lose progress; plan migration before doing so.

Use a separate test profile when replaying onboarding. Do not use a global DeleteAll operation in a buyer's existing multi-asset project. Developer resets and unlocks should be used deliberately on test saves. Confirm the state after stopping/restarting Play, because an old saved tutorial flag can correctly suppress the popup you expect to see.

The HLK settings asset is Assets/HyperCasualLiveOpsKit/Resources/HLK/HLKSettings.asset. Ads default to Dummy and IAP to Disabled. Keep those defaults while reskinning. A production provider requires its real, separately installed SDK, IDs, platform configuration and testing. Optional setup documentation does not mean a provider SDK is included or automatically installed. Keep service identifiers, ad-placement IDs and reward callback semantics separate from translated button text.
