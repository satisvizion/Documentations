Overview

Goods Sorting is a portrait drag-to-match shelf puzzle with 500 levels. Goods sit in three-slot boxes stacked in two to four columns; only the first rows of each column are on the shelf, the rest queue behind it. Drag a good into a free slot of another open box. Three matching goods clear a box, an emptied box also leaves the shelf, and the next queued box slides in. Chained boxes open after enough boxes have left. Clear every box to win; when no open box on the shelf has a free slot, the level is lost. The owner's original hand-made 3 × 17 shelf ships as level 500.

Getting Started

  1. Create or open a Unity 6000.0.62f1 project that uses the Universal Render Pipeline, the Input System package (activeInputHandler = Input System or Both) and Unity UI. Import TextMesh Pro Essential Resources when prompted.
  2. Import this package. Two roots appear: Assets/_GoodsSorting (game, engine scene, tools, resources) and Assets/HyperCasualLiveOpsKit (menu, economy, LiveOps, boosters).
  3. Assign a URP pipeline asset in Graphics/Quality settings and set Player → Color Space to Linear (the game was authored and tested in Linear; Gamma renders the shelf noticeably brighter). Assets/_GoodsSorting/ProjectRenderSettings contains the tested PC/Mobile pipeline and renderer assets.
  4. Add Assets/HyperCasualLiveOpsKit/StarterMenu/Scenes/HLK_MainMenu.unity first and Assets/_GoodsSorting/Scenes/Campaign.unity second to Build Settings. Play from the menu; the results overlay drives next level, replay and menu.
  5. Open Tools → GoodsSorting → Documentation to reopen this guide inside the editor.

Gameplay

  • Move: press a good in an open, unchained box on the shelf and release it over a free slot of another open box. Chained boxes accept nothing and release nothing.
  • Complete: a box holding three identical goods pops with a completion text and leaves the shelf.
  • Empty: a box whose last good is moved away also leaves the shelf — its three free slots go with it.
  • Queue: when a box leaves, everything above it in that column slides down and the next queued box appears.
  • Chains: a chained box shows a number; every box that leaves the shelf counts every visible chain down by one. At zero the box opens.
  • Loss: no free slot on any open box. A 1.5-second grace lets a booster rescue the shelf before the lose overlay.
  • Win: no boxes left anywhere; the kit credits 50 coins once and shows the results overlay.

Level Editor

Tools → GoodsSorting → Level Editor opens the shared level window with the shelf canvas. The left list selects a level; Duplicate/Delete/Up/Down and Undo (Ctrl+Z) edit the campaign; Validate + save publishes runtime JSON through staging only when every level validates and its witness replays.

  • Paint goods: pick a good in the palette, left-click a slot to place it, right-click to clear. The x cell erases.
  • Chains: in Chains mode click a box (left +1, right −1) or use Chain +/− on the selected box.
  • Boxes / structure: Insert box, Remove box, Columns +/−, Visible rows +/−. The dimmed band above the shelf is the queue.
  • Solve witness: edits clear the solution certificate; press Solve witness to let the bounded solver rebuild it (UNPROVEN means the search budget ran out, not that the level is impossible).
  • Play saved level: launches the saved level in the Campaign scene.

Automatic Level Generator

Tools → GoodsSorting → Auto Level Generator opens the same window; the Saved generation request block holds count, seed, attempts per level, minimum formations, maximum repeat streak and append mode. Generate into editor builds the campaign in memory (deterministic for a seed), validates every level's solver witness, colour-normalised uniqueness and structural variety, then Validate + save publishes. Append keeps the existing prefix. The shipped LevelTools/Data/CampaignBaseline.json records the generated campaign so later manual edits can be told apart; ExistingLevels.json records how the owner's authored shelf was assessed and placed.

Boosters

BoosterEffect
SHUFFLEEvery good on the open shelf swaps places (queue and chained boxes untouched); new matches may settle.
UNLOCKArm it, then tap a pulsing chained box; its chain breaks at once.
EXTRA TRAYAdds an empty tray beside the shelf for this attempt, up to three; rescues a shelf that just jammed.

Definitions live in _GoodsSorting/Integration/PowerUps; counts, unlock levels, copy and art are edited there. Each booster has its own AI-generated centre icon and explainer illustration under _GoodsSorting/Art/Boosters; swap those six PNGs to re-skin the bar without touching effects. See AI-DISCLOSURE.txt for their origin.

Level Variation

Chapters change one lever at a time: level 1 is a single drag, the queue appears at level 5, chains at 16, four columns at 36, then more goods types (up to 12), deeper queues, tighter free slots and more chains, with recovery levels every tenth level after 20. Structure is the column count, per-column queue depth silhouette, visible rows and chain layout — 490+ distinct formations across the 500 levels and never the same formation three times in a row. The frozen progression rules are encoded in GoodsProgression.

Customization Guide

  • Goods art: replace the PNGs in Game/Textures/Food (keep file names/meta) or edit ItemData.asset mappings.
  • Shelf art: Box prefab wood/chain textures in Game/Textures.
  • Difficulty: change GoodsProgression.Chapters (types, triples, free slots, hidden boxes, chains) and regenerate with a new seed, or hand-edit levels in the editor.
  • Boosters: counts/unlock levels in the PowerUp definition assets; effects in GameLevel.Boosters.cs.
  • DEV shortcut panel: the orange DEV button is deliberately visible in every build so you can try Choose Level (all 500 levels), test win/lose, banner/ad triggers and booster unlock/refill/reset. Before shipping your own store build, delete _GoodsSorting/Integration/GoodsSortingDevPanelPolicy.cs (or set StarterGameplayDevPanel.IsAvailable = false) so the kit's release gate hides it again.
  • Camera bands: GoodsSortingCameraFit.topBand/bottomBand reserve HUD and booster space.
  • Economy/LiveOps: see the HyperCasualLiveOpsKit guide (rewards, ads, IAP, quests, pass, minigames).

Level Format

Each Level_N.json is a GoodsJsonLevel: index, formation key, lesson, visibleRows, columns (each a list of boxes with three items, 0 = empty, 1–37 = goods type, and a chain count) and the solver witness as flat triples from-box, type, to-box (box ids count column by column from the bottom of each queue).

{
  "index": 3,
  "formation": "c2-v3-d2.1-k0",
  "lesson": "Match goods; an emptied box leaves",
  "visibleRows": 3,
  "columns": [
    { "boxes": [ { "items": [1, 2, 0], "chain": 0 }, { "items": [1, 1, 0], "chain": 0 } ] },
    { "boxes": [ { "items": [2, 2, 0], "chain": 0 } ] }
  ],
  "witness": [0, 1, 1, 0, 2, 2]
}

Safe worked editing procedure

  1. Open Level 4 in the Level Editor and duplicate it into an unused slot.
  2. Use the editor’s supported controls for a small placement change; keep legal occupancy and required targets. Do not invent JSON fields.
  3. Run the shipped validator, correct any rule errors, save, then open the duplicate in gameplay and complete it.
  4. For generation, record the current seed, request a small append batch using the exposed controls, validate its solutions and confirm the previous campaign prefix is unchanged. Cancelling must leave the campaign unchanged.

Run these procedures in a clean import of the final candidate before claiming buyer acceptance; restore test additions afterward.
