Brain Dots

Offline game and authoring guide. Open this file locally; no account or service is required for the drawing puzzle. Distribution, platform submission and monetization setup remain the buyer's responsibility.

Import and start

Use Unity 6000.0.62f1 with Universal Render Pipeline 17.0.4, Input System 1.8.1, UGUI 2.0.0, TextMeshPro and Unity's normal built-in modules. Install dependencies through Unity's Package Manager. Import the supplied archive into an empty project. Retain every .meta file; these identify scenes, sprites and materials. The principal roots are Assets/Game and Assets/HyperCasualLiveOpsKit. Unity's standard TextMesh Pro resources are retained as an explicit dependency exception. No third-party font is installed by this game.

Call BrainDots.EditorTools.PackageExport.RunFullSetup from your editor integration to configure existing scene references, Input System and supplied render assets. This configures files; it does not download a kit or generate gameplay. Open Assets/Game/Scenes/Game.unity to play the board directly. The supplied starter menu scene can be the first release scene if you choose to use that dependency. Its service adapters require your own configuration and review.

Play

Draw with the left mouse button or a single touch inside the board. Release to let the ink move under physics. Help the blue and pink dots touch. Some later levels can lose when a required dot leaves the play area. Retry is free and restarts the board. It preserves earned progress, coins and remaining booster stock; a charge already spent stays spent. There is no timer or promised rescue from every bad drawing. Use Retry when a position cannot be completed. A completed level can proceed to the next board.

Boosters

Rewind unlocks at level 2 and restores the board to before the latest drawing; earlier ink stays. Erase unlocks at level 7: select it, then select a piece of your ink; other ink remains. Select Erase again to cancel targeting. Nudge unlocks at level 12 and gives the two required dots a small inward push. It does not teleport them or guarantee completion. Stocked, unlocked effects are colored when usable on the current board. Empty, locked or currently unusable effects are gray. An unlocked empty booster remains selectable and opens acquisition offers. Unlocks follow earned progress. Each successful effect spends one charge. An invalid target or cancelled Erase spends none. Game policy grants two charges on first unlock; subsequent coin refills supply one charge, starting at 100 coins and increasing by 25 for each ten-level price step. See Resources/BrainDots/BoosterPolicy.json before changing policy. Optional rewarded-service controls need a real configured provider; no live ad delivery is represented here.

Levels and tools

Use Tools/Brain Dots/Documentation, Tools/Brain Dots/Level Editor and Tools/Brain Dots/Auto Level Generator. The editor resolves imported Resources/Levels data, so it works after relocation and without producer folders. Load a level by number, inspect dots/platforms, change normalized coordinates, duplicate a draft, or copy a draft to another destination slot. Edit > Undo restores draft edits. Publishing writes files; keep version-control backups for published changes. The first level is read-only; the editor also protects level 200. Duplicate a protected board before editing.

Geometry edits clear the stored winning witness. Solve current draft runs the bounded game solver. Publish is available only when replay of the legal-input witness wins. A solver failure means unproven, not impossible. The generator offers up to 64 geometry variants for unused numbers above 500. It creates a draft from supplied shapes and attempts a solution; it does not certify a new campaign or replace art. Review every changed level in real gameplay and review progression, obstacles, variety and performance before release. Copying into an existing destination replaces that slot on Publish; it does not automatically move the displaced level.

Data lives under Assets/Game/Resources/Levels. CampaignAuthoring.json binds layouts to input witnesses. Resource lookup keys remain Levels/Level_N, Levels/level-N and Levels/CampaignAuthoring. Render settings live under Assets/Game/ProjectRenderSettings. Keep their GUIDs intact. Five hundred published starting layouts have retained winning witnesses. Some bad-move states require Retry; winning continuations from those same states are not promised.

Audio and customization

Existing game event integration requests release, arrival, completion and failure sounds through the supplied audio dependency. The shared sound preference controls game cues and is persisted. Replace only assets you own, preserve required references and test mute, unmute and cold reload after changes. Subjective balance and device listening require your review. Use Unity's default TMP font and LegacyRuntime.ttf; this product does not fetch fonts. Existing public settings and game policy files can be adjusted with corresponding gameplay and save migration review.

Build and delivery

Install the Unity target module for your chosen platform, then build the included Boot and Game scenes. Configure optional service adapters and your platform's privacy disclosures before distribution. Device, service and store requirements depend on your chosen deployment.

Known limits

The game uses a deterministic 2D simulation. Small drawing changes, especially on dot-pile boards, can produce different trajectories. Free Retry provides recovery after an unhelpful drawing. Layout should be reviewed at your target aspect ratios. See Developer-Note.txt for product limitations. Licences and notices govern use of the included content; AI assistance is described in AI-DISCLOSURE.txt.

Scripts, variation and a level example

Bootstrap loads the Game scene. GameController accepts drawing input and advances the core Sim; GameUI and WorldView present the board. LevelCatalog resolves numbered Resources. BrainDotsBoosters supplies the three real effects; BrainDotsHlkBridge connects outcomes, game sounds and saved progress to the supplied dependency. BuyerLevelTools edits drafts; CampaignDraft and CampaignSolver support bounded candidate search. Vary existing dot/platform coordinates, supported shape arrangements and physics parameters only after reviewing changed play. Adding art or mechanics is your own development work.

Product limitations

  • The dots can continue settling after contact. Their final resting positions can vary with the drawing.
  • Level 200 uses input-sensitive dot-pile physics. Small changes in dot placement can change trajectories and completion time.
  • Game audio consists of drawing, arrival, completion and failure cues. The game does not include continuous background music. Typography uses Unity's default fonts.
  • Ink is rendered without a crayon texture. Tutorial pointers and completion stars are illustrative animations.
  • Geometry is two-dimensional. The legacy model-mode control changes its label only. Review layout on your intended device and aspect ratio.
  • Completion time depends on actual drawing and device scheduling. The game does not promise a fixed wall-clock completion time.

Review real-clock timing on your target device; a deterministic winning witness alone is not a device-performance guarantee.

Worked authoring examples

The generator is deterministic from New level number and Geometry variant (0â€“63). It has no editable random-seed control. Repeating the same pair produces the same geometry; changing the variant changes the supplied shape arrangement. A draft is not a proven level until the solver finds a legal winning witness.

  1. Open Tools/Brain Dots/Auto Level Generator. Set New level number to 501 and Geometry variant to 0. Click Create draft from supplied shapes. This creates an in-memory draft and runs the bounded solver; no published file changes.
  2. If the result is UNPROVEN, try variants 1 through 63 until Winning witness available appears. An unproven draft cannot be published. No claim is made that every variant is solvable.
  3. Click Publish validated draft for a winning draft. This appends Assets/Game/Resources/Levels/Level_501.json and a matching witness row to CampaignAuthoring.json. Existing level files and the original catalog prefix remain intact. Repeat with unused slot 502 to append a second level.
  4. Close the window before publication to cancel without changing files. Publishing an edited existing destination replaces that destination and its witness; it is not an append. The generator rejects slots 500 and below. The editor's protected baseline slots remain read-only.

Edit, validate, save and play

On a copy of the imported project, open Tools/Brain Dots/Level Editor, enter Level number 9 and click Load imported level. Click Duplicate as a new draft, set Destination slot to unused 503, and click Copy draft to destination slot. Select Platform 0. In Left / top / right / bottom, change only the left value from 0.48 to 0.481 (the JSON field is rects[0].minX). Geometry edits clear the witness. Click Solve current draft; publish only if a winning witness is available. Edit > Undo restores a draft operation before publication.

Click Publish validated draft, reload level 503, and confirm the platform left value is 0.481. Play the saved geometry using the core replay entry point CampaignDraft.Replay(savedJson, savedWitness, out simulation); the returned simulation must reach Phase.Won. This replays legal drawing inputs through the same game simulation. Also review ordinary player input, timing and presentation before using an edited level in your campaign. The shipped editor does not include a special playtest button or a random-seed field. To discard this example, restore the copied project or remove the new level and its matching authoring row together; do not remove only one.

Fields in the complete level example

levelId, levelNumber, title
Stable level identifier, positive numbered slot and displayed title.
aspect
Gameplay rectangle height divided by width. Coordinates use this rectangle, with the origin at its top left.
pen, penRadius
Pen style identifier and stroke radius normalized to gameplay width.
minInkSpacing, tapMaxMove
Minimum spacing between stored stroke points and movement threshold for a tap, normalized to gameplay width.
balls
Two target dots. Each has an id, center x/y, width-normalized diameter d, and HTML color.
rects
Supplied rectangular geometry. Each has an id, kind, normalized bounds minX/minY/maxX/maxY, and boolean collides.
physics.gravity
Downward acceleration in simulation world units. The simulation world width is 1000.
physics.friction, physics.density
Drawn-body surface friction and density.
physics.ballDensity, physics.ballFriction
Target-dot density and friction.
physics.iterations, physics.stepSeconds
Solver iterations and fixed simulation step in seconds. Changing these affects the replay contract.
feedback.resultDelayMs, feedback.popupDelayMs
Result presentation timing in milliseconds. A popup delay of -1 disables that popup.

The JSON example is the complete exported level 2. Optional tutorial and feedback fields in other levels are parsed by LevelData.FromJson; read that shipped parser before adding fields. Changes to physics, geometry or drawing parameters require a new winning witness and gameplay review.
