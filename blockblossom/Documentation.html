Block Blossom

First run

  1. Install Unity 6000.0.62f1 in Unity Hub. For Android add matching Android Build Support, SDK, NDK and OpenJDK; for browser builds add WebGL Build Support.
  2. Open the supplied standalone project, or create a Unity 6 URP project before importing the buyer package. Required packages: URP 17.0.4, uGUI 2.0.0, Input System 1.14.2, the standard Unity modules, ScreenCapture and AndroidJNI. The standalone project includes its manifest and lock file.
  3. Import the complete product folder. Keep its required subfolders together: Assets/SatisVizionBlockBlossom/Games/BlockBlossom, Assets/SatisVizionBlockBlossom/HyperCasualLiveOpsKit and Assets/SatisVizionBlockBlossom/TextMesh Pro. Keep every .meta file and the game's private Kit folder; it is required runtime code.
  4. Set Edit → Project Settings → Player → Other Settings → Active Input Handling = Both and restart Unity if prompted. Run Tools → Block Blossom → Setup after package import to select the supplied URP settings.
  5. Open Assets/SatisVizionBlockBlossom/Games/BlockBlossom/Scenes/BlockBlossom_Mobile.unity and press Play. This is the portrait scene. A landscape WebGL scene is also included; use the scene appropriate for your build. Much of the game UI and world are created at runtime.

Gameplay and content

Drag petal blocks from the three-piece tray into the garden bed. Complete rows and columns to clear them and work toward flower, watering, weed and nectar goals. Keep room for the next pieces.

Garden-shaped boards, flower and watering goals, weeds, bee-carrying pieces, combos, seeded piece dealing and shared bot-based authoring validation.

The source includes 25 authored levels and seeded procedural continuation. Progress, settings and charges are stored locally with PlayerPrefs. Browser storage depends on the browser profile. The template includes source and editable level data; generated continuation is not advertised as hundreds of individually authored levels.

Boosters

  • Trowel unlocks at level 4.
  • Seed Packet unlocks at level 7.
  • Rake unlocks at level 10.
  • Bee Swarm unlocks at level 15.

First-use guidance introduces each booster. Availability depends on the level, current state and remaining charges. Rewarded placements are simulated by default; only a completed reward callback should grant a refill. Use the DEV panel to unlock boosters for authoring, not as a substitute for real progression testing.

Booster usage and charges

The table lists the campaign unlock level and initial grant for each booster. Grants occur through the unlock/progression flow; existing local saves retain their stored inventory.

BoosterUnlockStarting chargesEffect and input
Trowel43Tap Trowel, then tap a filled garden block to dig it out. An empty garden has no valid target.
Seed Packet72Tap Seed Packet to replace the tray with three small pieces.
Rake102Tap Rake, then tap a garden row to clear it. Tap an armed targeted booster again to cancel.
Bee Swarm152Tap Bee Swarm to send helpers to eligible garden targets such as seeds, weeds or dry patches. It is unavailable when there is nothing to help.

The guided first use is free. Later completed uses consume one charge. Invalid actions are rejected by the game. Boosters depend on an active playable level; tutorials, popups and current effects can restrict activation. At zero charges, the refill offer awards exactly one charge only after a successful rewarded callback. Cancelling or failing that callback grants nothing. Shipping ads are simulated; production refills require your own separately configured provider. Charges and tutorial flags are saved locally through HzSave/PlayerPrefs. Tune BoostUnlock, BoostStart and the booster handlers in BlockBlossomGame.cs; keep UI guidance and actual rule logic consistent.

Manual editor and generation

Open Tools → Block Blossom → Level Editor. Duplicate a level before changing the original tutorial. The authoring file is Assets/SatisVizionBlockBlossom/Games/BlockBlossom/Resources/blockblossom/Levels/levels.json.

The editor paints the garden and configures its goal, seed, starting deals and Design difficulty. Seed cells bloom after clears; periodic bee pieces can act on seeds, weeds or dry patches. Auto Generate uses Seed, Start/End difficulty and Replace that range (else insert). Duplicate a non-tutorial level, rename it, inspect its goal and starting shapes, then Validate, Save and test it. Keep every named starting shape valid. Read the measured bot result before changing the deal or garden layout.

The included editor supports saving, duplication and ordering, and provides generation and validation controls appropriate for this game. Read the actual validation result; a difficulty target is not a guarantee of player success. Use a repeatable seed when comparing generated variants. Test changed boards in Play mode.

Customisation

Game logic is under Scripts; presentation and UI are in the game's Game partial classes. Artwork, sound effects, music and levels are under Resources/blockblossom. Shared UI, audio, ad and haptic helpers live in Kit/Runtime; font files and placements are under Kit/Resources/blockblossom/kit. Keep resource paths unless you update every matching code reference.

Change Company Name, Product Name, Version and the Android application identifier in Player Settings to values you control. Do not publish under com.satisvizion.blockblossom.demo. Assign your own launcher/adaptive icon layers and review the splash screen, in-game title and other branding. Increase Android Bundle Version Code for each released update. Test UI fit, text and touch targets on an actual phone.

LiveOps, ads and haptics

The publisher-owned HyperCasual LiveOps Kit is included. Read its complete offline manual.

Settings: Assets/SatisVizionBlockBlossom/HyperCasualLiveOpsKit/Resources/HLK/HLKSettings.asset. Shipping defaults are Ads Mode Dummy (0) and IAP Mode Disabled (3). Banner, interstitial and rewarded placements are simulations. No Google Mobile Ads, billing or other vendor SDK is included. Automatic vendor-SDK installers are disabled. The game's own Kit is required code, not an advertising SDK.

To enable a real provider, separately install its official SDK, follow the kit manual, configure your own identifiers, consent and privacy policy, then test the selected platform and all cancellation/failure cases. Do not enable SDK symbols without the corresponding dependency. Optional kit modules are capabilities, not production services already configured for this game. Native vibration needs a supported device; browser haptics and other native services have platform limits.

Development controls

Open DEV, press F2/backquote, or use the kit's top-left multi-tap shortcut. The global panel supports level jumps, booster access, ads and haptics controls. Add HZ_RELEASE to scripting defines when you want these development controls excluded from a consumer build. This does not configure real ads or certify store readiness.

Android release

Use the Mobile scene, portrait orientation and ARM64/IL2CPP with matching Unity tools. The provided APK is a debug-signed, non-development showcase demo, not a production store release. For release keep Development Build and debugging off, choose your own application identifier and review current store API requirements.

In Player → Publishing Settings create or select your own keystore and alias. Securely retain the keystore, alias and passwords for future updates; never redistribute signing secrets. Enable Build App Bundle for a Google Play AAB. Install a release candidate on a physical Android device and check touch, audio, haptics, pause/resume, saves and any enabled provider flows. Complete destination-store ads/data declarations and your privacy policy for the services actually enabled.

WebGL

Build the Mobile scene for a portrait-only demo with the built-in Default template and Brotli decompression fallback. Use Tools → Block Blossom → Create Responsive WebGL Page after building and select the output folder. This generates an original responsive page around the complete Build folder. Serve every loader, framework, data and WASM file over HTTP(S); file:// is unsupported. Audio normally starts after a first click/tap.

The two-scene landscape-first route supports ?mobile=1 to switch to the following Mobile scene. The included WebGL build menu uses HLK's non-development local showcase scope. It supports simulated demos; configure your production providers and resolve the kit build-doctor checks for a real service release.

Source map and a first edit

All required assets are grouped under Assets/SatisVizionBlockBlossom. Keep the game, its own Kit, HyperCasualLiveOpsKit and TextMesh Pro together.

  • Games/BlockBlossom/Scenes: supplied mobile and landscape entry scenes.
  • Games/BlockBlossom/Scripts: game-specific rules and presentation.
  • Games/BlockBlossom/Editor: game-specific authoring tools; shared build/editor helpers also live in the game's Kit.
  • Games/BlockBlossom/Resources/blockblossom: editable campaign data, artwork and game-specific audio resources.
  • Games/BlockBlossom/Kit/Runtime: required game-framework helpers, including saving, audio, ad/haptic integration and developer controls.
  • HyperCasualLiveOpsKit: the included publisher-owned service kit and its own manual.
  • TextMesh Pro: included text resources and retained licence notices.

Main source roles:

  • BlockBlossomGame and its Hud/View partials: input, goals, tutorials and presentation.
  • BmData / BmLevels: level schema and campaign loading.
  • BmEngine: placement, clearing, goals and helper rules.
  • BmGen / BmBot / BmArt: generation, bot evaluation and resource lookup.

First edit, step by step: open the game's Level Editor from Tools, select a non-tutorial level, click Duplicate (or Dup), change its Name, run Validate, read the result and click Save. Click Play this level in that same editor to start the selected board. Check the changed name, play the goal and retry once. Exit Play mode before further authoring. For a rule or geometry edit, repeat validation and play the full level; a bot success alone does not certify the human experience. Keep a backup of levels.json before replacing a generated range.

Troubleshooting

  • Missing types: install the required packages and import all three roots, preserving .meta files.
  • Pointer input exception: select Active Input Handling Both and restart Unity.
  • Pink materials: use URP 17.0.4 and run the game's Setup command.
  • Sparse scene in edit mode: world/UI objects are built at runtime; press Play.
  • No real ad revenue: Dummy mode is simulated and no provider SDK is bundled.
  • IAP is unavailable: it is deliberately Disabled by default; configure an official billing integration separately if you need it.
  • Progress persists: use the development reset controls or deliberately clear this product's PlayerPrefs.
  • WebGL does not load from a local file: serve the complete output over HTTP(S).
