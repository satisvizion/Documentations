Gameplay

Click or tap a bolt, then another bolt. Only a matching top colour or an empty bolt can receive a move; available space limits how many nuts transfer. Filled single-colour bolts receive a cap. Rust hides colours until exposed, a key nut opens a padlocked bolt when moved away, and tall bolts hold five nuts.

The first levels guide the basic moves. New mechanics and boosters introduce themselves through popups. Completion awards gears: 20 for a normal level or 40 for a hard level, plus any other earned gears. Progress, charges and settings save locally through PlayerPrefs; WebGL storage depends on the browser profile. When no legal move remains, the recovery popup offers applicable undo/spare/retry actions.

The source renders its workshop, bolts and nuts using procedural meshes and URP materials, with uGUI overlays. The interaction is a tap-based sorting puzzle. Use the supplied scene and camera setup for its workshop presentation.

Level editing

Open Nut Bolt Sort â†’ Level Editor. The editor reads and writes Assets/Games/NutSort/Resources/nutsort/Levels/levels.json.

To make a first edit:

  1. Select an existing level in the list and duplicate it, keeping the original tutorial unchanged.
  2. Select a bolt, choose a nut colour, and paint the bolt from bottom to top. Use the erase brush to remove that slot and the nuts above it. Keep colour totals consistent with the bolt capacity.
  3. Adjust bolt capacity, rust, key position and the optional padlocked bolt. The key must be on a different bolt from the lock.
  4. Run the editor's validation/solver controls. Read the actual result; a design difficulty value is a target, not a proof that a player will solve it.
  5. Save the level file. In Play mode open the DEV panel and jump to the new level number. Play the changed board and confirm its intended solution.

The editor supports add, duplicate, delete, reorder, undo and save prompts. Nut Bolt Sort â†’ Validate All Levels is available for authoring validation.

The top nut is normalised clean by the runtime. A winning bolt is full and all one colour. Keep the model's maximums in mind: 12 colours, 16 bolts and capacity up to 6; the delivered design uses four- and five-nut bolts.

Generation

The editor's Auto Generate controls include count/start, seed, empty bolts, colour range, rust range, difficulty range, breathers, locks, tall bolts, spread layout and replacement. Generate a small batch, inspect its solver/difficulty results, save, then play the new boards.

After the 25 authored levels, NsLevels.Get uses NsGen.Curve and the deterministic seed level * 7919 + 1301. Generated levels cycle through breather, rust, lock, combined and hard recipes. The generator uses bounded solver attempts, alternate seeds, extra room and a constructive fallback. The delivered content is 25 authored levels plus procedural continuation.

Boosters

Booster Unlock Initial charges Effect
Undo 3 3 Reverses a recorded move.
Hint 5 2 Shows a suggested next move.
Spare Bolt 8 2 Adds one empty bolt, once per level and within the model's bolt limit.
Rust Spray 10 2 Choose a rusty bolt to clean its rust.

When a usable booster has no charges, its popup offers one charge for 60 gears when affordable or a rewarded-ad refill. A reward is granted only when the ad callback reports completion. Failed/skipped/unavailable ads do not grant a reward. Tutorial guidance can temporarily restrict unrelated actions.

LiveOps and ads

Included LiveOps asset: HyperCasual LiveOps Kit. Its complete offline manual is included alongside the game.

Configuration: Assets/HyperCasualLiveOpsKit/Resources/HLK/HLKSettings.asset. The delivered configuration uses Ads Mode Dummy, with simulated banner, interstitial and rewarded ads and no advertising provider SDK. Integration is via Kit/Runtime/HzAds.cs, HzPlatform, and the three placement assets under Kit/Resources/nutsort/kit/Ads.

The banner reserves layout space. Interstitials occur at natural progression breaks. Rewarded ads support booster refill and eligible recovery actions. These are simulation features for development/showcase, not live revenue-generating ads. Public sample ad-unit identifiers, where present, are test identifiers. Do not enable SDK scripting symbols for packages you have not installed. Other HLK services are configurable kit capabilities; the game does not claim every kit service is configured for production.

Builds

Android: select the Mobile scene, Android build target, portrait orientation, your own application identifier, ARM64/IL2CPP and matching Unity Android tools. The supplied demo is a development APK signed with a debug key. It is not a signed production AAB or a Google Play submission. Configure your own signing and release settings for publication.

WebGL: select the Mobile scene for the portrait demo, the Default WebGL template, and build with Unity's WebGL module. Serve the entire output over HTTP(S). Keep loader, framework, data and WASM files together; opening index.html via file:// is unsupported. Brotli with Unity decompression fallback is suitable for a static host. Browser audio normally needs the first click/tap. Native services and haptics have browser limitations.

For the supplied standalone project's two-scene landscape-first route, ?mobile=1 switches to the following Mobile scene. A portrait-only build should simply use the Mobile scene without that switch.

Troubleshooting

  • Missing types after import: install the documented Unity packages, import all three required roots, and keep .meta files.
  • Pointer input exceptions: set Active Input Handling to Both and restart the editor.
  • Pink materials or wrong rendering: use URP 17.0.4 and the supplied NutSort pipeline/renderer; run Setup and select the built-in WebGL template.
  • No real ad revenue: Dummy mode is simulated. A separately configured provider and its SDK are required for real ads.
  • A booster is unavailable: check its unlock level, charges, current tutorial/guide, and whether its action is applicable.
  • An imported scene appears sparse in edit mode: UI and workshop objects are built at runtime. Press Play.
  • Progress persists between tests: use the developer reset controls; clearing PlayerPrefs removes saved progress/settings.
  • An external URL is unavailable offline: this manual and the included kit manual are local HTML. External provider links require internet.
