Overview and included content

Select a piece and then a legal destination. Follow forced captures and finish any capture chain. The active rule variant and opponent profile determine the available moves and challenge.

Twenty-five opponent profiles, twenty-one authored combo puzzles, multiple checkers rule variants, AI search and four chess-independent helper systems.

This is an editable Unity template for developers. The supplied game is a working starting point; use the included source, assets and authoring tools to produce your own title. The template contains 25 authored opponent profiles and 21 authored combo puzzles. The game keeps its required private runtime Kit and the publisher-owned HyperCasual LiveOps Kit together in one product folder.

The shipping service configuration uses simulated Dummy ads and Disabled IAP. Advertising, billing, analytics and other optional provider SDKs are not bundled or automatically installed. A simulation is useful for testing callbacks and user-interface flow; it does not establish live advertising revenue, purchases, cloud storage or a production backend. The Android APK is a debug-signed showcase, not your release signing key or a marketplace submission.

Read the installation steps before pressing Play. Read the reskin recipes before replacing colours or text, and use the level editor before changing JSON by hand. Both portrait and landscape entry scenes are supplied. The offline HTML and PDF manuals contain the same practical guidance, so a purchaser can begin before visiting the hosted documentation.

Requirements and installation

  1. Extract the main download completely into a normal writable folder. Keep the native Unity package, source project and offline documentation available while setting up. Back up an existing project before importing a new template.
  2. Use Unity 6000.0.62f1. In Unity Hub, install Android Build Support with its matching SDK, NDK and OpenJDK for Android builds, and WebGL Build Support for browser builds. Do not substitute a different NDK simply because another application installed one.
  3. For the supplied standalone source project, choose Add project in Unity Hub and select the Unity Project directory containing Assets, Packages and ProjectSettings. Do not select the enclosing storefront-material folder as a Unity project.
  4. For package import, create a Universal Render Pipeline project, open Assets > Import Package > Custom Package and import the complete native package. Retain Assets/SatisVizionCheckersClub, including its game, private Kit, HyperCasualLiveOpsKit, TextMesh Pro, fonts, settings and metadata. Import into a clean project first when diagnosing an integration problem.
  5. Check Window > Package Manager for Universal RP 17.0.4, Unity UI 2.0.0 and Input System 1.14.2. The standalone manifest also lists the standard Unity modules used by the template, including com.unity.modules.screencapture and com.unity.modules.androidjni. These are Unity dependencies; optional advertising and billing packages are separate.
  6. Open Edit > Project Settings > Player > Other Settings > Active Input Handling, select Both and restart the Editor if Unity requests it. This is a manual prerequisite. The buyer template does not secretly inspect or change that setting during import, domain reload or Play mode.
  7. Allow package resolution and script compilation to finish. Resolve red Console errors before opening several tools at once. A missing Input System namespace usually means its package did not resolve; an input exception often means the Both setting or restart was missed.
  8. In Project Settings > Graphics, assign the supplied CheckersClub_URP.asset from Assets/SatisVizionCheckersClub/Games/CheckersClub/Settings. Check the pipeline assignment for the active Quality level as well. Retain the matching renderer and generated global/volume settings. A missing renderer or wrong pipeline can produce pink materials or a blank world.
  9. Open Assets/SatisVizionCheckersClub/Games/CheckersClub/Scenes/CheckersClub_Mobile.unity for portrait. Press Play, focus the Game view and follow the first introduction. Use the landscape Assets/SatisVizionCheckersClub/Games/CheckersClub/Scenes/CheckersClub_WebGL.unity scene for the alternate layout. Stop Play before changing persistent source or assets.
  10. Save the project after setup. Record the engine/package versions that worked and keep a clean copy. If you later upgrade Unity or URP, treat that as a separate migration: back up, update deliberately and repeat the gameplay, authoring and build checks.

First play, controls and progression

Play local checkers against the authored opponent ladder, or choose a supplied Combo Puzzle. Select your piece and a legal destination; follow the current rule set for captures, multi-jumps and kings. Opponent profiles can change the starting odds and which side you play. The ladder records match results and cherries, while puzzles have their own positions and completion goals. Read rule/introduction cards before the first move. Helpers are Hot Tip, Rewind, Spotlight and Coach; internal IDs remain hint, undo, spot and coach.

Select a piece and then a legal destination. Follow forced captures and finish any capture chain. The active rule variant and opponent profile determine the available moves and challenge.

Start with the opening content rather than a late challenge selected from developer controls. Read the goal and any first-time mechanic hint, perform the indicated gesture, and watch the goal counters change. The tutorial is part of the real game flow. A control may remain unavailable while a popup, introduction, animation or guided step is active; confirm or complete that step before interpreting a tap as broken input.

The current goal determines success. Check the displayed remaining shots, time, moves, tray capacity, opponents or picture progress as appropriate for this game. A successful result advances the normal progression and invokes the configured reward/ad hooks. Failure follows the game-specific retry or recovery flow. Developer jump, unlock and charge controls exist for testing; they are not evidence that a challenge was completed through normal play.

Test a new visual theme in the opening scene and a later challenge. Small counters, disabled helpers, result dialogs, pause/settings, long hint text and the alternate orientation often reveal layout problems that a title screen does not. Confirm that a UI element is still readable against the background, has a useful touch target and does not cover the play area. Keep essential colour distinctions visible after a palette change.

Progress, first-use hints, unlocked content and helper charges are stored locally by the game. Stop Play before editing authored assets. A runtime change to a generated UI object usually disappears when the scene is rebuilt. Use the documented source assignments, level editor and save controls to make a permanent change.

Opponent ladder and tactical-position authoring

This game has two distinct authored collections: opponents and puzzles. The supplied counts are 25 ladder profiles and 21 puzzle positions. An opponent profile contains visible identity/dialogue and AI/setup parameters. A tactical position contains board-state and solution/goal information. Editing one collection does not automatically rewrite the other.

For a safe ladder reskin, duplicate a non-opening opponent and change Name, Title, Accent and the visible introduction/win/lose lines shown by this editor. Preserve rule identifiers, position notation, helper unlock IDs and side-to-move values unless you intend a rule/setup change. Search depth, node budget, mistake margin, noise and style settings affect strength in different ways; increasing several together is not a reliable linear difficulty curve.

For a tactical position, use the position editor/notation fields and the correct side to move. Retain required kings and legal piece placement, then run the relevant validation/solution check. A legal position is not necessarily a solved tactical puzzle, and an engine evaluation is not a promise that a human player will find the solution quickly. Test the hint path, forced replies and completion condition after changing a position.

Automatic generation and difficulty tuning

Exact Checkers Club insertion/replacement behavior: For opponents, Replace range OFF appends to the end of the ladder. ON removes the available requested range and inserts generated opponents at its start. Start step is one-based when replacing; the normal append path derives placement from the existing opponent count. The separate puzzle generator always appends its generated combo puzzles and does not use the opponent replacement toggle.
