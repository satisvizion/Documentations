Block Grid Master

Version 1.0.0 · SatisVizion · Unity 6000.0.62f1 · URP 17.0.4

Drag glass panes from the three-piece tray onto the window. Complete rows and columns to clear them and meet the commission goal within its pane budget. Free Glazing provides an endless score mode.

First run

  1. Install Unity 6000.0.62f1 in Unity Hub. For Android add matching Android Build Support, SDK, NDK and OpenJDK; for browser builds add WebGL Build Support.
  2. Open the supplied standalone project, or create a Unity 6 URP project before importing the buyer package. Required packages: URP 17.0.4, uGUI 2.0.0, Input System 1.14.2, the standard Unity modules, ScreenCapture and AndroidJNI. The standalone project includes its manifest and lock file.
  3. Import the complete product folder. Keep its required subfolders together: Assets/SatisVizionBlockGrid/Games/BlockGrid, Assets/SatisVizionBlockGrid/HyperCasualLiveOpsKit and Assets/SatisVizionBlockGrid/TextMesh Pro. Keep every .meta file and the game's private Kit folder; it is required runtime code.
  4. Set Edit → Project Settings → Player → Other Settings → Active Input Handling = Both and restart Unity if prompted. Run Tools → Block Grid Master → Setup after package import to select the supplied URP settings.
  5. Open Assets/SatisVizionBlockGrid/Games/BlockGrid/Scenes/BlockGrid_Mobile.unity and press Play. This is the portrait scene. A landscape WebGL scene is also included; use the scene appropriate for your build. Much of the game UI and world are created at runtime.

Gameplay and content

Drag glass panes from the three-piece tray onto the window. Complete rows and columns to clear them and meet the commission goal within its pane budget. Free Glazing provides an endless score mode.

Shaped window boards, commission goals, pane budgets, line and score targets, gems, glow cells, seeded generation and Free Glazing unlocked from level five.

The source includes 25 authored levels and seeded procedural continuation. Progress, settings and charges are stored locally with PlayerPrefs. Browser storage depends on the browser profile. The template includes source and editable level data; generated continuation is not advertised as hundreds of individually authored levels.

Boosters

  • Rotate unlocks at level 3.
  • Undo unlocks at level 6.
  • Fresh Panes unlocks at level 10.
  • Sunburst unlocks at level 15.

First-use guidance introduces each booster. Availability depends on the level, current state and remaining charges. Rewarded placements are simulated by default; only a completed reward callback should grant a refill. Use the DEV panel to unlock boosters for authoring, not as a substitute for real progression testing.

Booster usage and charges

The table lists the campaign unlock level and initial grant for each booster. Grants occur through the unlock/progression flow; existing local saves retain their stored inventory.

BoosterUnlockStarting chargesEffect and input
Rotate33Tap Rotate, then tap a tray pane to turn it before placement. Tap the booster again to cancel targeting.
Undo62Tap Undo after a placement to restore the saved previous placement state. It is unavailable before a move exists.
Fresh Panes102Tap Fresh Panes to redeal the tray. Fixed commission queues cannot be swapped.
Sunburst152Tap Sunburst, then tap the window to shatter the3-by-3 area around that cell. Tap the booster again to cancel targeting.

The guided first use is free. Later completed uses consume one charge. Invalid actions are rejected by the game. Boosters depend on an active playable level; tutorials, popups and current effects can restrict activation. At zero charges, the refill offer awards exactly one charge only after a successful rewarded callback. Cancelling or failing that callback grants nothing. Shipping ads are simulated; production refills require your own separately configured provider. Charges and tutorial flags are saved locally through HzSave/PlayerPrefs. Tune BoostUnlock, BoostStart and the booster handlers in BlockGridGame.cs; keep UI guidance and actual rule logic consistent.

Manual editor and generation

Open Tools → Block Grid Master → Level Editor. Duplicate a level before changing the original tutorial. The authoring file is Assets/SatisVizionBlockGrid/Games/BlockGrid/Resources/blockgrid/Levels/levels.json.

The editor exposes Name, Pane budget, Deal difficulty and Seed, with board painting and goal-specific controls. It supports Validate/Validate All and seeded generation with Start/End difficulty and Replace that range (else insert). Duplicate a non-tutorial commission and rename it. A small increase in Pane budget is a useful first change when that goal uses a budget. Validate, Save and test it. Inspect gems, glow cells and line/score targets when changing board geometry; the bot measures different goals differently.

The included editor supports saving, duplication and ordering, and provides generation and validation controls appropriate for this game. Read the actual validation result; a difficulty target is not a guarantee of player success. Use a repeatable seed when comparing generated variants. Test changed boards in Play mode.

Customisation

Game logic is under Scripts; presentation and UI are in the game's Game partial classes. Artwork, sound effects, music and levels are under Resources/blockgrid. Shared UI, audio, ad and haptic helpers live in Kit/Runtime; font files and placements are under Kit/Resources/blockgrid/kit. Keep resource paths unless you update every matching code reference.

Change Company Name, Product Name, Version and the Android application identifier in Player Settings to values you control. Do not publish under com.satisvizion.blockgrid.demo. Assign your own launcher/adaptive icon layers and review the splash screen, in-game title and other branding. Increase Android Bundle Version Code for each released update. Test UI fit, text and touch targets on an actual phone.

LiveOps, ads and haptics

The publisher-owned HyperCasual LiveOps Kit is included. Read its complete offline manual.

Settings: Assets/SatisVizionBlockGrid/HyperCasualLiveOpsKit/Resources/HLK/HLKSettings.asset. Shipping defaults are Ads Mode Dummy (0) and IAP Mode Disabled (3). Banner, interstitial and rewarded placements are simulations. No Google Mobile Ads, billing or other vendor SDK is included. Automatic vendor-SDK installers are disabled. The game's own Kit is required code, not an advertising SDK.

To enable a real provider, separately install its official SDK, follow the kit manual, configure your own identifiers, consent and privacy policy, then test the selected platform and all cancellation/failure cases. Do not enable SDK symbols without the corresponding dependency. Optional kit modules are capabilities, not production services already configured for this game. Native vibration needs a supported device; browser haptics and other native services have platform limits.

Development controls

Open DEV, press F2/backquote, or use the kit's top-left multi-tap shortcut. The global panel supports level jumps, booster access, ads and haptics controls. Add HZ_RELEASE to scripting defines when you want these development controls excluded from a consumer build. This does not configure real ads or certify store readiness.

Android release

Use the Mobile scene, portrait orientation and ARM64/IL2CPP with matching Unity tools. The provided APK is a debug-signed, non-development showcase demo, not a production store release. For release keep Development Build and debugging off, choose your own application identifier and review current store API requirements.

In Player → Publishing Settings create or select your own keystore and alias. Securely retain the keystore, alias and passwords for future updates; never redistribute signing secrets. Enable Build App Bundle for a Google Play AAB. Install a release candidate on a physical Android device and check touch, audio, haptics, pause/resume, saves and any enabled provider flows. Complete destination-store ads/data declarations and your privacy policy for the services actually enabled.

WebGL

Build the Mobile scene for a portrait-only demo with the built-in Default template and Brotli decompression fallback. Use Tools → Block Grid Master → Create Responsive WebGL Page after building and select the output folder. This generates an original responsive page around the complete Build folder. Serve every loader, framework, data and WASM file over HTTP(S); file:// is unsupported. Audio normally starts after a first click/tap.

The two-scene landscape-first route supports ?mobile=1 to switch to the following Mobile scene. The included WebGL build menu uses HLK's non-development local showcase scope. It supports simulated demos; configure your production providers and resolve the kit build-doctor checks for a real service release.

Source map and a first edit

All required assets are grouped under Assets/SatisVizionBlockGrid. Keep the game, its own Kit, HyperCasualLiveOpsKit and TextMesh Pro together.

  • Games/BlockGrid/Scenes: supplied mobile and landscape entry scenes.
  • Games/BlockGrid/Scripts: game-specific rules and presentation.
  • Games/BlockGrid/Editor: game-specific authoring tools; shared build/editor helpers also live in the game's Kit.
  • Games/BlockGrid/Resources/blockgrid: editable campaign data, artwork and game-specific audio resources.
  • Games/BlockGrid/Kit/Runtime: required game-framework helpers, including saving, audio, ad/haptic integration and developer controls.
  • HyperCasualLiveOpsKit: the included publisher-owned service kit and its own manual.
  • TextMesh Pro: included text resources and retained licence notices.

Main source roles:

  • BlockGridGame and its Hud/View partials: input, commissions, tutorials and presentation.
  • BgData / BgLevels: level schema and campaign loading.
  • BgLogic / BgSession: board rules, goals, budgets and session state.
  • BgGen / BgArt / BgSfx: generation, artwork lookup and sound references.

First edit, step by step: open the game's Level Editor from Tools, select a non-tutorial level, click Duplicate (or Dup), change its Name, run Validate, read the result and click Save. Click Play this level in that same editor to start the selected board. Check the changed name, play the goal and retry once. Exit Play mode before further authoring. For a rule or geometry edit, repeat validation and play the full level; a bot success alone does not certify the human experience. Keep a backup of levels.json before replacing a generated range.

Troubleshooting

  • Missing types: install the required packages and import all three roots, preserving .meta files.
  • Pointer input exception: select Active Input Handling Both and restart Unity.
  • Pink materials: use URP 17.0.4 and run the game's Setup command.
  • Sparse scene in edit mode: world/UI objects are built at runtime; press Play.
  • No real ad revenue: Dummy mode is simulated and no provider SDK is bundled.
  • IAP is unavailable: it is deliberately Disabled by default; configure an official billing integration separately if you need it.
  • Progress persists: use the development reset controls or deliberately clear this product's PlayerPrefs.
  • WebGL does not load from a local file: serve the complete output over HTTP(S).
