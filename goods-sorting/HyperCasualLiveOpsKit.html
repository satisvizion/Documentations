Overview

HyperCasualLiveOpsKit provides the starter menu, results overlays, local progression/economy, ads and purchase interfaces, power-up presentation and service configuration. This buyer projection contains runtime systems. AI integration/setup scripts and internal validation tools remain in the separate developer source kit.

Setup

Use Unity 6000.0.62f1 with URP 17.0.4, Input System 1.14.2 and Unity UI 2.0.0. Import TMP Essential Resources. In the supplied Goods Sort game, HLK_MainMenu precedes GameNew in build scenes and the game bridge is already connected. For a different game use the full developer kit and Phase02 saved adapter workflow; importing this buyer projection alone does not discover arbitrary game rules.

Included Systems

The shared runtime includes menu/navigation, results, settings, coin/progression persistence, booster inventory and a development panel with level selection. Mock ads are dismissible and their overlays block underlying interaction. LocalQA purchase and rewarded-ad flows exercise UI/economy without certifying a live provider.

Keep each game adapter responsible for its own win/loss events and boosters. Do not replace working game mechanics to match the example.

Configuration

Inspect StarterMenuConfig and the HLK/PowerUps resources in the Inspector. Set scene names, visible level count, economy rewards and service selections deliberately. Real service IDs, consent policy, privacy URL, production signing and native-device acceptance are owner responsibilities. Back up saves before changing progression keys.

Validation and Limits

The development source provides automated setup, economy/UI checks and build/release audits. The Goods Sort Phase08 run passed desktop gameplay and local economy journeys and built a LocalQA ARM64 APK. Device startup, lifecycle, notches, Android back, real ads/IAP and audible listening remain unverified. Never treat a mock reward or build success as live-service acceptance.
